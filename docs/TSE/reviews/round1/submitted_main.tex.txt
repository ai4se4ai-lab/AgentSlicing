\title{Agent Slicing: Contracts for Sub-Teams Expose and Localize Blind Spots in Multi-Agent AI Systems}

\author{Anonymous Authors%
\thanks{Manuscript submitted to IEEE Transactions on Software Engineering.}}

\markboth{IEEE Transactions on Software Engineering}%
{Agent Slicing: Contracts for Sub-Teams of Multi-Agent AI Systems}

\maketitle

\begin{abstract}
Software teams increasingly build systems in which several AI agents hand work to one another: an analyst writes a specification, an architect a design, a developer code, a reviewer a verdict. Such a team can be unsafe even when every agent meets its own contract, because the defect lives in a relationship among agents: a join that releases on the first approval, two reviewers that share one model, a test gate that relies on tests written by a fallible agent. Checks that look at one agent at a time, or only at the final output, either miss these defects or cannot say where they are. We introduce \emph{agent slicing}. A slice is a convex, possibly disconnected, set of agents in the team graph, analyzed as a component with its own contract: entry assumptions, guarantees, and emergent obligations that no single member carries. We define slices, their derived and declared contracts and a semantics for graph-shaped teams with fork, join (all, any, quorum), switch and deterministic gates. We prove that slice-level analysis recovers agent-level analysis exactly, that it is strictly more expressive, that slice abstraction is compositional over partitions with an acyclic quotient, and that a change to one agent invalidates only a computable set of slices. A blind spot's \emph{depth} is the size of its smallest manifesting slice; depth at least two means invisible at agent level. On a benchmark of \resBenchTotal{} generated teams with injected ground-truth defects, \resHiddenRate{} of the defects are hidden at agent level; agent-level analysis finds \resRecallHiddenkOne{} of the hidden ones and slice-level analysis finds \resRecallHiddenSL{}, with no false alarm on clean and decoy teams. A whole-team checker detects them too but localizes a defect to \resLocRatioBTwo{} of the team on average; slicing localizes to \resLocRatioSL{} and returns the exact minimal slice in \resLocExactSL{} of cases. In encodings of \resArchDesigns{} published multi-agent designs, under contracts we declared from their documentation, \resArchHiddenDocumented{} contain a defect that only slices reveal. The study is formal and simulated; it does not claim that any language model satisfies a contract.
\end{abstract}

\begin{IEEEkeywords}
Multi-agent systems, large language models, assume-guarantee reasoning, contracts, compositional verification, fault localization, slicing.
\end{IEEEkeywords}

\section{Introduction}
\IEEEPARstart{L}{arge} language model (LLM) agents are now composed into teams that do software work. MetaGPT assigns the roles of a software company (product manager, architect, engineer, QA) to agents that exchange documents in a fixed order~\cite{hong2024metagpt}; ChatDev runs a chat chain of design, coding, review and testing phases~\cite{qian2024chatdev}; AgentCoder lets a programmer agent and a test-designer agent work in parallel and runs the tests with a script~\cite{huang2023agentcoder}; Agentless and MAGIS split issue resolution into localization, repair and validation stages~\cite{xia2025agentless,tao2024magis}. Surveys in software engineering list dozens of such designs~\cite{he2025llmmas,hou2024llm4se,fan2023llmse}, and general frameworks such as AutoGen make it easy to wire agents into new topologies~\cite{wu2024autogen}.

These teams are engineered artifacts, so we should be able to ask an engineering question about them before they run: \emph{is the composition justified?} If every agent does what its contract says, does the team deliver what the team promises? Current practice answers a different question. Benchmarks such as SWE-bench and AgentBench score the final output of a run~\cite{jimenez2024swebench,liu2024agentbench,yehudai2025survey}. Guardrails and runtime enforcement check a single agent's inputs, outputs or actions~\cite{inan2023llamaguard,rebedea2023nemo,wang2026agentspec}, and security benchmarks probe one agent against injected content~\cite{debenedetti2024agentdojo,greshake2023not,ruan2024toolemu}. Failure studies of multi-agent systems collect traces after the fact and attribute a failure to an agent and a step~\cite{cemri2025why,zhang2025which}.

These approaches share two limits. First, they judge \emph{one agent at a time} or \emph{the whole team at once}. Second, they need executions. Cemri et al.\ report that a large share of failures in multi-agent LLM systems come from inter-agent misalignment and from verification steps that do not verify~\cite{cemri2025why}. Such failures are properties of a relationship among agents. Consider a release gate that ships when either the developer or the security tester approves. Each agent can meet its contract, and the gate's policy is itself legal, yet the team can ship code that was never security tested. Inspecting any single agent shows nothing wrong. Inspecting the final output shows a missing property, but not \emph{which} part of the team let it through.

Assume-guarantee reasoning gives the right vocabulary: each component assumes something about its inputs and guarantees something about its outputs, and a composition is justified when every assumption is discharged by some guarantee~\cite{misra1981proofs,jones1983tentative,abadi1993composing,benveniste2018contracts}. Applied naively at the level of single agents, however, it is not path-sensitive. It credits a fact to a consumer if \emph{some} upstream agent claims it, even if a join may drop that branch or a switch may route around it. It also treats guarantees as unconditional, although an agent's guarantee holds only when its own inputs were right and its model did not fail. We show that this agent-level check is silent on whole classes of defects (Section~\ref{sec:approach}).

\textbf{This paper.} We propose \emph{agent slicing}. Program slicing taught us to study the part of a program that matters for a criterion~\cite{weiser1984program,horwitz1990interprocedural}. We study \emph{parts of a team}. A slice is a set of agents that is convex in the team graph: every path between two members stays inside. Slices need not be connected: two parallel reviewers form a slice. We give each slice a contract, consisting of \emph{entry assumptions} that no member establishes internally, \emph{guarantees} that hold on every behavior of the slice, and \emph{emergent obligations} that belong to the slice as a whole (joint coverage of parallel branches, independence of two members' evidence, absence of a bypass). We then look for blind spots slice by slice. The size of the smallest slice in which a blind spot becomes visible is its \emph{depth}. Depth one means visible at agent level; depth two or more means hidden. The smallest manifesting slices \emph{localize} the defect: they name the relationship that is wrong, not just an agent or the final output. Fig.~\ref{fig:overview} shows the idea.

We make the idea precise for graph-shaped teams. A team is a directed acyclic graph of agents (whose guarantees are conditional and whose model may fail) and deterministic gates (programs such as a test runner). Nodes can \emph{fork} (deliver to all successors), \emph{switch} (deliver to one), and \emph{join} with an \texttt{all}, \texttt{any} or \texttt{quorum} policy. The semantics is exact: a team is unsafe if some contract-respecting behavior releases an output that lacks a promised property. A slice is analyzed in a \emph{hybrid} semantics: members behave exactly, everything outside is taken at face value. This one definition yields agent-level analysis (singleton slices), whole-team analysis (the slice of all nodes), and everything in between.

We study three research questions.

\textbf{RQ1, Formal foundation and expressiveness.} \emph{Can an agent slice be defined as a first-class contract such that slice-level reasoning is sound and compositional, recovers agent-level analysis as a special case, and is strictly more expressive than it?}

\textbf{RQ2, Detection and localization power.} \emph{How many blind spots does slice-level analysis reveal that agent-level analysis cannot, and how precisely does it localize their root causes, compared with agent-level and whole-team analysis?}

\textbf{RQ3, Cost, slicing strategy, and evolution.} \emph{What does slice-level analysis cost, how do slicing strategy and slice size trade detection power against cost and false alarms, and how much re-verification does slicing save when a team evolves?}

\textbf{Contributions.}
\begin{itemize}
\item A calculus of graph-shaped agent teams with fork, switch, join policies, conditional guarantees, oracle failures, and local declared evidence, with an exact semantics and a worst-case lemma that reduces all contract-respecting models to finitely many runs (Section~\ref{sec:background}).
\item \emph{Slices as contracts}: convex slices, a hybrid semantics, derived and declared slice contracts, emergent obligations, and slicings with an explicit acyclic-quotient condition (Section~\ref{sec:approach}).
\item A taxonomy of blind spots (agent-level classes A1--A4 and slice-level classes S1--S6) with the notions of \emph{depth} and \emph{minimal manifesting slice}.
\item Eight theorems: conservativity (T1), slice abstraction (T2), soundness (T3), separation with parametric families and a fooling-set argument (T4), localization with a counterexample to monotonicity (T5), merging of overlapping findings (T6), complexity (T7), and incremental recertification (T8). Their per-node steps are discharged by an SMT solver, and every theorem is checked against brute-force oracles on \resConformanceComparisons{} comparisons with zero mismatches.
\item An implementation with seven slicing strategies, an injector of ground-truth defects, a topology generator, and a replication package that regenerates every number in this paper with one command.
\item An evaluation on \resBenchTotal{} generated teams, nine encoded published designs, teams of up to \resScaleMaxNodes{} nodes, and \resEvoChanges{} evolution steps.
\end{itemize}

\textbf{Main results.} Of the injected defects, \resHiddenRate{} are hidden at agent level (depth $\ge 2$). The agent-level checker finds none of the slice-level classes; the combined slicing strategy finds all of them without a false alarm on \resCleanTeams{} clean and \resDecoyTeams{} decoy teams. An exact whole-team checker detects the same defects, so the gain of slicing is not detection alone. It is \emph{localization}: the whole-team checker's explanation covers \resLocRatioBTwo{} of the team on average, while the slice checker points to \resLocRatioSL{} of it and returns the exact minimal slice in \resLocExactSL{} of cases. Detection saturates at slice size $k=\resSaturationK$. Strategies with small slices scale polynomially to thousands of agents; on switch-free teams exact whole-team checking is cheaper still, while on choice-rich teams both whole-team checking and large slices hit time limits. After a change, only \resEvoRedoneNonChain{} of the slices need re-verification on non-chain topologies. On unstructured random teams, \resWildFARate{} of slice findings are false alarms, which a witness replay refutes.

\textbf{Scope.} We ask whether a composition is justified \emph{given the declared contracts} of its parts. We do not claim that any LLM satisfies a contract, and we do not show that any deployed team became safer. All experiments are deterministic or seeded simulations on a CPU; no language model is called.

\section{Background: Agent Teams and Their Semantics}\label{sec:background}

This section fixes a small model of agent teams. We keep only what we need to state when a team is safe.

\subsection{Agents, Gates and Contracts}

A team works on a shared artifact, for example a code change, and builds up facts about it: a design exists, tests exist, the tests pass. We call such facts \emph{properties} and write $\Props$ for the finite set of properties a team mentions. A component \emph{requires} some properties before it can do its job, and it \emph{guarantees} others when it does its job. This is design by contract~\cite{meyer1992applying} applied to team members.

Two kinds of components matter. An \emph{agent} is driven by a language model. Its guarantee is \emph{conditional}: it holds only when the agent's requirements are met and its model (its \emph{oracle}) does not fail. A \emph{gate} is a deterministic program, such as a test runner or a schema check. A gate's guarantee is conditional on its requirements but never on a model. The distinction lets us ask what still holds if up to $f$ models misbehave.

An agent may also \emph{declare} evidence for itself, for example ``I read the specification''. Declared evidence counts when we decide whether that agent can act, but it is \emph{local}: it never flows to other components. A statement by an agent is not a fact for others unless a component that is entitled to guarantee it does so.

\begin{definition}[Team]\label{def:team}
A \emph{team} is a tuple $T=(N,E,\iota,\omega,\kappa,\req,\gua,\decl,\orc,\rt,\jn)$ with goals $\Phi\subseteq\Props$, critical goals $\Phi_c\subseteq\Phi$, and a fault budget $f\in\mathbb{N}$, where:
\begin{itemize}
\item $(N,E)$ is a finite directed acyclic graph with a unique source $\iota$ (the input) and a unique sink $\omega$ (the output);
\item $\kappa(n)\in\{\mathsf{agent},\mathsf{gate}\}$; $\iota$ and $\omega$ are gates;
\item $\req(n),\gua(n),\decl(n)\subseteq\Props$ are the requirements, guarantees and declared evidence of $n$; $\gua(\iota)$ are the input facts, and $\req(\omega)=\Phi$;
\item $\orc(n)\in\Orc$ names the oracle of each agent; agents may share an oracle;
\item $\rt(n)\in\{\mathsf{fork},\mathsf{switch}\}$ says whether $n$ delivers to all successors or to exactly one;
\item $\jn(n)\in\{\mathsf{all}\}\cup\mathbb{N}_{\ge 1}$ is the join policy of a node with several predecessors; \texttt{any} is the quorum $1$.
\end{itemize}
Every node lies on a path from $\iota$ to $\omega$ and is reached in some fault-free run (Definition~\ref{def:run}).
\end{definition}

We write $\pred(n)$ and $\succs(n)$ for direct predecessors and successors, and $\anc(n)$ and $\desc(n)$ for proper ancestors and descendants. A switch with one successor is a fork.

\subsection{Runs}

A run resolves every choice the team leaves open. Three kinds of choices exist: which successor a switch picks, which delivered inputs a quorum or \texttt{any} join actually uses, and which oracles fail.

\begin{definition}[Run]\label{def:run}
A \emph{run} $\rho=(W,C,F)$ chooses a successor $W(n)$ for each switch, a contributor set $C(n)$ for each node with several predecessors, and a set $F\subseteq\Orc$ of failed oracles with $|F|\le f$. A run is \emph{fault-free} if $F=\emptyset$. In topological order:
\begin{enumerate}
\item $\iota$ is reached, with content $c(\iota)=\emptyset$ and output $o(\iota)=\gua(\iota)$;
\item an edge $(u,v)$ is \emph{delivered} if $u$ is reached and $u$ is a fork or $W(u)=v$; let $D(v)$ be the delivered in-edges of $v$;
\item $v$ is reached if $D(v)$ meets its policy: all in-edges for \textsf{all}, at least $q$ for quorum $q$; then $C(v)\subseteq D(v)$ with $|C(v)|\ge q$ (for \textsf{all}, or a single in-edge, $C(v)=D(v)$);
\item the content is $c(v)=\bigcup_{(u,v)\in C(v)} o(u)$;
\item $v$ \emph{applies} if $\req(v)\subseteq c(v)\cup\decl(v)$ and $v$ is a gate or $\orc(v)\notin F$;
\item the output is $o(v)=c(v)\cup\gua(v)$ if $v$ applies, and $o(v)=c(v)$ otherwise.
\end{enumerate}
\end{definition}

Properties flow along the contributing lineage. A join that uses one branch forgets what the other branch established; this is what makes \texttt{any} and quorum joins interesting. Declared evidence appears in step~5 but not in step~6, so it is local.

\subsection{Symptoms and Safety}

A team can go wrong in three ways that we can observe at a node: a component acts without a property it requires, the output misses a goal, or the output misses a critical goal when up to $f$ oracles fail. We name each by a \emph{key}, a triple of kind, node and property.

\begin{definition}[Symptoms, safety]\label{def:sym}
The \emph{symptoms} $\Sym(T)$ of a team are the keys
\begin{itemize}
\item $\key{assume}{v}{p}$: some fault-free run reaches $v\neq\omega$ with $p\in\req(v)\setminus(c(v)\cup\decl(v))$;
\item $\key{goal}{\omega}{\varphi}$: some fault-free run reaches $\omega$ with $\varphi\in\Phi\setminus c(\omega)$;
\item $\key{robust}{\omega}{\varphi}$: $\key{goal}{\omega}{\varphi}\notin\Sym(T)$, and some run with $|F|\le f$ reaches $\omega$ with $\varphi\in\Phi_c\setminus c(\omega)$.
\end{itemize}
$T$ is \emph{safe} if $\Sym(T)$ contains no goal or robust key, and \emph{clean} if $\Sym(T)=\emptyset$.
\end{definition}

An \texttt{assume} key is a defect even when the output is fine: some agent was asked to act on a fact nobody established. A \texttt{robust} key says that a critical goal rests on a model behaving well.

\subsection{From Models to Runs}

The semantics above is concrete. The guarantee we want is about \emph{all} behaviors that respect the contracts. In such a behavior, a component may know more than its content; for example, an agent may happen to see a fact that nobody guaranteed. We model this with \emph{evidence}: in a contract-respecting model, each node has evidence $E(v)\supseteq c(v)\cup\decl(v)$ and applies if $\req(v)\subseteq E(v)$ and its oracle has not failed; the output meets goal $\varphi$ if $\varphi\in E(\omega)$. The following lemmas show that runs, and only a few of them, are enough.

\begin{lemma}[Worst case, W]\label{lem:w}
A key is produced by some contract-respecting model if and only if it is produced by some run.
\end{lemma}

\begin{lemma}[Minimal choices, M]\label{lem:m}
Content is monotone in the contributor sets and antitone in the failure set. To decide $\Sym(T)$ it suffices to enumerate runs whose quorum joins use exactly $q$ contributors and whose failure sets are maximal ($|F|=\min(f,|\Orc|)$).
\end{lemma}

\begin{lemma}[Halting, H]\label{lem:h}
Allowing a reached node to deliver nothing creates no new symptom.
\end{lemma}

The idea behind Lemma~\ref{lem:w} is that more evidence can only make more components apply, which can only add properties downstream; the minimal evidence $c(v)\cup\decl(v)$ is therefore the worst case. Lemmas~\ref{lem:m} and~\ref{lem:h} use the same monotonicity. Proofs are in Appendix~\ref{app:proofs}; the per-node steps are SMT obligations (Section~\ref{sec:rq1}).

\textbf{Chain.} A requirements analyst (RA) writes a specification; an architect (AR) turns it into a design; a developer (DV) writes code and tests; a security reviewer (SR) reviews the code; a deterministic test runner (TS) runs the tests and guarantees \p{tests\_pass}. Look at each component alone. RA needs nothing. AR needs \p{req\_spec}, which RA guarantees upstream. DV needs \p{design}, guaranteed by AR. SR needs \p{code}, guaranteed by DV. TS needs \p{tests}, guaranteed by DV. The critical goal is guaranteed by a \emph{gate}, so it seems not to depend on any model. Every assumption is matched. An agent-level check reports nothing.

Yet the team is not robust. If model $g$ fails at DV, DV produces no tests, TS cannot apply, and \p{tests\_pass} is missing. The defect is neither in DV (it is allowed to fail; $f=1$) nor in TS (it behaves correctly). It lies in the relationship: \emph{a deterministic gate's critical guarantee rests on a fallible agent's provision.} The smallest set of components in which this shows is $\{$DV, SR, TS$\}$; SR is included because a slice must be convex.

\textbf{Fork-join.} The analyst forks work to an architect (AR) and a threat modeler (TM). AR feeds a developer (DV), which guarantees \p{implemented}. TM feeds a security tester (ST), which guarantees \p{sec\_tested}. Both feed a release gate (RG) with policy \texttt{any}: release on the first approval. Again every requirement is matched, every goal is claimed by some ancestor of the output, and no agent is a single point of failure. Agent-level analysis is silent. But a run in which RG uses only ST's input releases code that is not implemented, and a run that uses only DV's input releases code that was not security tested. The defect lives in the join and one branch: $\{$DV, RG$\}$ and $\{$ST, RG$\}$ each show it.

\section{Agent Slicing}\label{sec:approach}

We now define slices, give them a semantics and a contract, and state what slice-level analysis can and cannot do. Each step is followed by the running example.

\subsection{Overview}

The analysis takes a team specification and a \emph{slicing strategy}. The strategy proposes slices. For each slice, the analysis enumerates the slice's internal behaviors while treating the rest of the team at face value, and it records every symptom it sees together with a witness run. It then reports each symptom with its smallest manifesting slices, a mechanism class, and the witness. A separate certification step decides safety: either with the slice of all nodes or compositionally with a partition (Theorem~\ref{thm:abs}).

\subsection{Slices}

A slice should be a well-defined sub-computation: work that enters it should not leave it and come back. Otherwise the slice's behavior would depend on what happens outside in the middle of its own computation. Convexity captures this.

\begin{definition}[Slice]\label{def:slice}
A \emph{slice} is a nonempty set $\sigma\subseteq N$ that is \emph{convex}: for all $u,w\in\sigma$, every path from $u$ to $w$ lies in $\sigma$. Its \emph{entry edges} $\InE(\sigma)$ go from outside into $\sigma$; its \emph{exit edges} $\OutE(\sigma)$ go from $\sigma$ to outside. The \emph{hull} $\hull(S)=\anc^*(S)\cap\desc^*(S)$ is the smallest convex superset of $S$, where $\anc^*$ and $\desc^*$ include $S$ itself.
\end{definition}

Connectedness is not required. In the fork-join team, $\{$DV, ST$\}$ is a slice: there is no path between the two, so convexity holds trivially. $\{$RA, DV$\}$ is not a slice, because the path RA$\to$AR$\to$DV leaves it; its hull is $\{$RA, AR, DV$\}$.

\begin{lemma}[Convexity]\label{lem:convex}
If $\sigma$ is convex, no node outside $\sigma$ is both an ancestor and a descendant of nodes of $\sigma$. Hence the outside predecessors of members have no member among their ancestors, and contracting $\sigma$ to a single node leaves an acyclic graph. Conversely, if contracting $\sigma$ (all other nodes kept) leaves a DAG, $\sigma$ is convex.
\end{lemma}

\subsection{Hybrid Semantics and Findings}

To analyze a slice in isolation we must say what the rest of the team does. We take it at \emph{face value}: every outside component is assumed to do its job. This is the classical assume-guarantee stance, applied to everything except the slice.

\begin{definition}[Hybrid semantics]\label{def:hybrid}
Let $\cone(v)=\gua(\iota)\cup\bigcup_{u\in\anc(v)}\gua(u)$ be the properties claimed upstream of $v$. The hybrid semantics $H_\sigma$ is defined like Definition~\ref{def:run} with these changes. Runs choose only member switches, member contributor sets, and failures $F\subseteq\orc(\sigma)$ with $|F|\le f$. Every \emph{outside} node is reached if it is $\iota$ or some in-edge is delivered; all its delivered in-edges contribute; it always applies and delivers to all successors. Every entry edge into a member $v$ is always delivered and carries $\env_\sigma(v)=\bigcup_{u\in\pred(v)\setminus\sigma} o(u)$. The \emph{findings} $\Fd{\sigma}$ are the keys of Definition~\ref{def:sym} evaluated in $H_\sigma$, at every node.
\end{definition}

By Lemma~\ref{lem:convex}, the outside predecessors of a member are never influenced by members, so $\env_\sigma(v)$ is a fixed set: the face-value output of those predecessors. Outside nodes \emph{below} members are recomputed in each run; this is how a slice's internal failure becomes visible at the output.

Two special cases anchor the definition. With $\sigma=N$ nothing is outside, so $H_N$ is the exact semantics and $\Fd{N}=\Sym(T)$. With the empty set every node applies and delivers everywhere; its findings $\Fd{\emptyset}$ are the requirements and goals that no ancestor claims at all. The central technical fact is that taking a node at face value never hides less than analyzing it exactly:

\begin{lemma}[Face value dominates, A]\label{lem:face}
Let $\sigma\subseteq\sigma'$ and let $\rho'$ be a run of $H_{\sigma'}$, and let $\rho$ be the run of $H_\sigma$ that makes the same choices on $\sigma$ and fails $F'\cap\orc(\sigma)$. Every node reached in $\rho'$ is reached in $\rho$, and its content in $\rho'$ is a subset of its content in $\rho$.
\end{lemma}

So symptoms in a large slice come from \emph{less} content, never more. The converse direction, from a small slice to a large one, can fail; we return to it in Theorem~\ref{thm:loc}.

\subsection{Agent-Level Analysis}

What does it mean to check a team agent by agent? The natural reading is: check each agent against its own contract, assuming every other component meets its contract. That is exactly the hybrid semantics of a singleton slice.

\begin{definition}[Agent-level analysis]\label{def:al}
$\AL(T)=\bigcup_{v\in N}\Fd{\{v\}}$.
\end{definition}

\begin{proposition}[What agent level sees]\label{prop:al}
For every node $v$, $\Fd{\emptyset}\subseteq\Fd{\{v\}}$. Every key in $\Fd{\{v\}}\setminus\Fd{\emptyset}$ has a witness in which $v$ does not apply (its requirements are not claimed upstream, or its oracle fails) or $v$ is a switch that routes away from a claimer.
\end{proposition}

The proposition explains the silence in the running example. A join's singleton slice sees the \emph{union} of all its inputs (they are outside, at face value), so a join's policy never matters at agent level. Two agents on one model are never seen failing together, and a gate never sees that its input came from a model. In the chain, $\Fd{\{v\}}=\emptyset$ for every $v$: the singleton $\{$DV$\}$ can fail, but TS outside still applies at face value.

\begin{theorem}[Conservativity, T1]\label{thm:conserv}
The singleton slicing reports exactly $\AL(T)$, the per-agent assume-guarantee check with every other component at face value. Agent-level findings are characterized by Proposition~\ref{prop:al}, and $\Fd{\emptyset}\subseteq\AL(T)$.
\end{theorem}

\subsection{Slice Contracts}

A slice is a component, so it should have a contract. We distinguish the contract the semantics \emph{implies} from the contract an engineer \emph{writes}.

Within a slice, a member's requirement may be established by another member, or it may have to come from outside. Only the latter belong in the slice's assumptions. Likewise, the slice guarantees only what holds on every one of its behaviors, not what some member claims.

\begin{definition}[Derived slice contract]\label{def:contract}
For a slice $\sigma$ and an environment $X\subseteq\Props$ carried by every entry edge:
\begin{itemize}
\item the \emph{entry assumptions} $A_\sigma$ are the pairs $(v,p)$ with $v\in\sigma$, $p\in\req(v)$, such that some fault-free internal run of $\sigma$ with empty environment reaches $v$ without $p$ in $c(v)\cup\decl(v)$;
\item the \emph{guarantee} $G_\sigma(X)$ is the intersection, over all fault-free internal runs and all delivered exit edges, of the output that crosses the exit when every entry carries $X$; the \emph{robust guarantee} $G^f_\sigma(X)$ is the same over runs with $|F|\le f$;
\item the \emph{naive guarantee} $N_\sigma(X)$ is what composing member contracts at face value promises: $X$ plus every member guarantee upstream of each exit, intersected over exits;
\item the \emph{emergent obligations} $X_\sigma$ are the relational conditions whose violation makes $G_\sigma(X)\subsetneq N_\sigma(X)$ (or $G^f_\sigma\subsetneq G_\sigma$): joint coverage at joins, non-bypass at switches, conditional backing of a guarantee, and independence of oracles. A finding classifies the gap $N_\sigma(X)\setminus G_\sigma(X)$ by the obligation that fails.
\end{itemize}
\end{definition}

Table~\ref{tab:contracts} shows derived contracts for the running example. For $\{$DV, SR, TS$\}$ the fault-free guarantee equals the naive one, but the robust guarantee loses \p{tests}, \p{code} and \p{tests\_pass}: the obligation ``the critical guarantee is backed by a non-fallible provider'' fails. For $\{$SR, TS$\}$, with \p{tests} supplied from outside, the robust guarantee keeps \p{tests\_pass}. So the slice that \emph{explains} the defect must contain DV. For $\{$ST, RG$\}$ the naive guarantee contains \p{sec\_tested} but the derived one does not: the join-coverage obligation fails.

\begin{definition}[Declared contract]\label{def:declared}
A \emph{declared contract} of $\sigma$ is a pair $(A^d,G^d)$ of property sets. It is \emph{valid} if, when every entry carries $A^d$, every member's requirements hold in every fault-free internal run and $G^d\subseteq G_\sigma(A^d)$.
\end{definition}

A derived contract is in general \emph{not} a single assumption-guarantee pair. If $\sigma$ has two independent members, $m_1$ requiring $r_1$ and guaranteeing $g_1$, and $m_2$ requiring $r_2$ and guaranteeing $g_2$, then the slice guarantees $g_1$ when $r_1$ arrives and $g_2$ when $r_2$ arrives. No single pair $(A,G)$ says this. The exact contract is a relation.

\begin{definition}[Boundary behavior]\label{def:beh}
$\Beh_\sigma$ maps each delivery pattern of the entry edges, each assignment of contents to entry edges, and each failure set to the set of possible outcomes: which exits are delivered, with what content, and which keys arise at members.
\end{definition}

\begin{theorem}[Slice abstraction, T2]\label{thm:abs}
\begin{enumerate}
\item[(a)] Replacing a slice by a macro component whose behavior is $\Beh_\sigma$ leaves $\Sym(T)$ unchanged.
\item[(b)] Let $f=0$. If $(A^d,G^d)$ is valid and the team in which $\sigma$ is replaced by a component that, whenever its entries carry $A^d$, delivers $G^d$ on its exits (and otherwise behaves arbitrarily) is safe, then $T$ is safe.
\item[(c)] No single pair $(A,G)$ is exact for the slice of two independent members.
\item[(d)] For a partition of $N$ into convex parts whose quotient graph is acyclic, $\Sym(T)$ equals the symptoms obtained by composing the parts' boundary behaviors in the quotient's topological order. Convex parts alone do not suffice: $\{a,d\}$ and $\{b,c\}$ with edges $a\to b$ and $c\to d$ are convex and their quotient has a cycle; with a cyclic quotient, flat $(A,G)$ part contracts admit circular reasoning that certifies an unsafe team.
\end{enumerate}
\end{theorem}

\emph{Proof idea.} (a) and (d) hold because a part's outcomes are a function of what crosses its entries; we track a member's content symbolically as the set of entry edges whose content reaches it plus what members add, so the summary does not depend on the rest of the team. The acyclic quotient gives an order in which every part's inputs are known before the part runs. (b) follows from (a), because the declared component over-approximates $\Beh_\sigma$. (c) is a finite countermodel, checked by SMT. For the circular example, add $\iota\to a$, $\iota\to c$, $b\to\omega$, $d\to\omega$; let $a$ and $d$ require $y$ and guarantee $x$, and $b$ and $c$ require $x$ and guarantee $y$. The part contracts ``$\{a,d\}$: assume $y$, guarantee $x$'' and ``$\{b,c\}$: assume $x$, guarantee $y$'' are both valid (Definition~\ref{def:declared}) and discharge each other, but neither $x$ nor $y$ is ever established: $a$ and $c$ act without their requirements.

\subsection{Checking Slices and Soundness}

Algorithm~\ref{alg:check} is the slice-level checker. For each slice it enumerates the minimal internal runs (Lemma~\ref{lem:m}) by depth-first search over member choices. Members without choices are evaluated in a loop. After each internal run, the effect on outside descendants is propagated in topological order, and propagation stops at nodes whose content equals their face-value content. The findings of all slices are merged by key (Theorem~\ref{thm:overlap}), and each key is localized to its inclusion-minimal manifesting slices.

\begin{algorithm}[!t]
\caption{Slice-level checking and localization}\label{alg:check}
\begin{algorithmic}[1]
\REQUIRE team $T$, family of slices $\mathcal{S}$, run budget $B$
\STATE $S_0 \leftarrow \Fd{\emptyset}$ \COMMENT{face-value cone, linear time}
\STATE $M \leftarrow$ empty map from keys to slices
\FORALL{$\sigma\in\mathcal{S}$}
  \FORALL{$F\in\{\emptyset\}\cup\{F\subseteq\orc(\sigma):|F|=\min(f,|\orc(\sigma)|)\}$}
    \FORALL{minimal internal run $\rho$ of $\sigma$ with failures $F$ (DFS; abort after $B$)}
       \STATE evaluate members in topological order
       \STATE propagate to outside descendants until content equals face value
       \STATE add each new key $\kappa$ of $H_\sigma$ to $M[\kappa]$ with witness $\rho$
    \ENDFOR
  \ENDFOR
\ENDFOR
\FORALL{keys $\kappa$ in $M$}
  \STATE $\MMS(\kappa)\leftarrow$ inclusion-minimal slices in $M[\kappa]$, ranked by size, then by number of choice points
  \STATE classify $\kappa$ by replaying the witness on the top slice (Table~\ref{tab:classes})
\ENDFOR
\RETURN $S_0$, $M$, $\MMS$, classes
\end{algorithmic}
\end{algorithm}

\begin{theorem}[Soundness, T3]\label{thm:sound}
\begin{enumerate}
\item[(a)] If the family contains $N$, or if certification uses a partition with an acyclic quotient (Theorem~\ref{thm:abs}d), the checker's verdict ``safe'' implies that $T$ is safe, and each reported counterexample is a run of $T$.
\item[(b)] A finding $\kappa\in\Fd{\sigma}$ is a symptom of $T$ if its witness \emph{lifts}: some run of $T$ makes the same member choices, delivers the entry edges the witness uses, and reaches the symptom node.
\item[(c)] Without a lift, a finding can be a false alarm.
\end{enumerate}
\end{theorem}

Part (c) is not hypothetical. Consider a team of gates. The input feeds a switch $s$ and a provider $y$ that guarantees the goal $g$. The switch sends its work either to $x$ or directly to the output. Gate $x$ joins $s$ and $y$ with \texttt{any}. The output joins $s$ and $x$ with \texttt{all}. In the team, the output is reached only when $s$ routes to it; then $x$ receives only $y$'s input, and $g$ arrives at the output. The team is clean. In the slice $\sigma=\{s,x,y\}$ the output is outside and taken at face value, so it is reached as soon as one input arrives. The slice's run in which $s$ routes to $x$ and $x$ uses only $s$'s input misses $g$ at the output. That run has no counterpart in the team, because there the output would need both inputs. Section~\ref{sec:rq3} measures how often this happens.

\subsection{Depth and Localization}

\begin{definition}[Depth, minimal manifesting slices]\label{def:depth}
A slice $\sigma$ \emph{manifests} a key $\kappa$ if $\kappa\in\Fd{\sigma}$. If $\kappa\in\Fd{\emptyset}$, its depth is $1$ and it is localized at its node. Otherwise its \emph{depth} is the minimum size of a manifesting slice, and $\MMS(\kappa)$ is the set of inclusion-minimal manifesting slices. A blind spot is \emph{hidden at agent level} if its depth is at least $2$.
\end{definition}

In the running example, the chain's robust loss of \p{tests\_pass} has depth \resRexChainDepth{} with a unique minimal slice $\{$DV, SR, TS$\}$. Each goal loss of the fork-join team has depth \resRexFjDepth{} with \resRexFjMinimal{} minimal slices, $\{$DV, RG$\}$ and $\{$ST, RG$\}$.

\begin{theorem}[Separation, T4]\label{thm:sep}
\begin{enumerate}
\item[(a)] For each class S2, S3, S4, S6a and S6b there is a family of teams, parametric in the length $\ell$ of the hand-off chain between the interacting components and in the number of branches, in which agent-level analysis reports no key of the defect (for S6b: not the goal key), the team is unsafe or unclean, and a slice of size $2$ (S2, S3) or $\ell+2$ (S4, S6a, S6b) manifests and localizes the defect. Chains realize S4, S6a and S6b; fork-join regions realize S2 and S3.
\item[(b)] For S2, S4 and S6a there are safe teams whose singleton \emph{views} (a node's own contract, kind, oracle and policy, and the set of properties claimed upstream) together contain every singleton view of the unsafe team. Hence no analysis that decides from singleton views is both sound and free of false alarms on these classes.
\item[(c)] Recovery: for every live node $v$, every key located at $v$ in $\Fd{\{v\}}$ is in $\Fd{\sigma}$ for every slice $\sigma\ni v$.
\end{enumerate}
\end{theorem}

Part (b) is a lower bound on any agent-local method, not only ours. For S4: two reviewers on oracles $(o_1,o_2)$ and on $(o_2,o_1)$ give safe teams; the unsafe team uses $(o_1,o_1)$, and each of its reviewers looks exactly like one reviewer of a safe team. Part (c) says nothing found at agent level is lost by looking at larger slices; with (a), slice-level analysis is strictly more expressive.

\begin{theorem}[Localization, T5]\label{thm:loc}
\begin{enumerate}
\item[(a)] If $\kappa\in\Sym(T)$ then $\MMS(\kappa)\neq\emptyset$.
\item[(b)] $\MMS(\kappa)$ need not be a single slice; it is a single slice if and only if the intersection of the minimal manifesting slices manifests $\kappa$.
\item[(c)] For every witness run of $\kappa$ in $T$, the hull of the witness's contributing lineage of the symptom node manifests $\kappa$ (for a robust key: $\kappa$ or the goal key of the same property). Hence $\depth(\kappa)$ is at most the size of the smallest such hull.
\item[(d)] If $\kappa\in\Fd{\sigma}$ and its witness lifts to $H_{\sigma'}$ for $\sigma\subseteq\sigma'$, then $\kappa\in\Fd{\sigma'}$. A witness always lifts when $\sigma'\setminus\sigma$ contains no switch and no \textsf{all} or quorum join.
\item[(e)] Without a lift, monotonicity fails: there are teams and slices $\sigma\subset\sigma'$ with $\kappa\in\Fd{\sigma}\setminus\Fd{\sigma'}$.
\end{enumerate}
\end{theorem}

Part (e) uses the false-alarm team above: the alarm in $\sigma$ disappears in a larger slice that contains the output. Larger slices are therefore not simply ``better''. They can remove false alarms as well as reveal deeper defects.

\begin{theorem}[Overlap and cover, T6]\label{thm:overlap}
Keys do not depend on the slice that produced them, so findings from overlapping slices merge by key without double counting. A slice only reports the presence of keys and never certifies their absence, so findings of different slices cannot contradict each other. A family detects every key that has a manifesting slice in the family; the family of all convex slices of size at most $k$ detects every key of depth at most $k$.
\end{theorem}

\subsection{Slicing Strategies and Complexity}

\begin{definition}[Slicing]\label{def:slicing}
A \emph{slicing} is a family of slices. A \emph{partition slicing} partitions $N$ into slices whose quotient graph is acyclic. A \emph{covering slicing} is any family; its slices may overlap.
\end{definition}

We compare eight strategies. \emph{Singleton} is agent level. \emph{Whole} is the slice $N$. \emph{Window-$k$} takes, for each node, the hull of the node and its descendants within $k-1$ hops; on a chain these are the intervals of length $k$ (Fig.~\ref{fig:overview}c). \emph{Band-$w$} takes the hull of $w$ consecutive longest-path levels, a cross-section of parallel branches (Fig.~\ref{fig:overview}e). \emph{Region} takes single-entry single-exit regions: each fork or switch with its immediate post-dominator, each join with its immediate dominator, and each join with its direct predecessors~\cite{johnson1994program,lengauer1979fast}. \emph{Goal-directed} is the analogue of a backward slice~\cite{weiser1984program}: for each requirement $(v,p)$, the hull of $v$, the ancestors that claim $p$, and the ancestors that claim those claimers' requirements. \emph{Random} draws convex slices of matched sizes (a control). \emph{Exhaustive-$k$} takes every convex slice of size at most $k$. The combined strategy \emph{SL} is singleton $\cup$ window-2 $\cup$ region $\cup$ goal-directed.

\begin{theorem}[Complexity, T7]\label{thm:cx}
\begin{enumerate}
\item[(a)] Deciding $\kappa\in\Sym(T)$ is NP-complete, and deciding safety is coNP-complete, already for teams of gates only, without forks, and with $f=0$.
\item[(b)] Computing $\Fd{\sigma}$ takes $O(R_\sigma\cdot(|N|+|E|)\cdot\lceil|\Props|/w\rceil)$ time, where $R_\sigma$ is the number of minimal internal runs and $w$ the machine word size; $R_\sigma$ is bounded by the product of member switch fan-outs, the binomial coefficients of member quorum joins, and $1+\binom{|\orc(\sigma)|}{f}$, so it is polynomial when the number of member choice points and $f$ are bounded.
\item[(c)] A team can have $2^{\Theta(|N|)}$ convex slices; all convex slices of size at most $k$ are enumerated with $O(|N|^k)$ hull tests.
\item[(d)] Singleton, window, band and region strategies produce $O(|N|)$ slices, computable in $O(|N|(|N|+|E|))$ total time; goal-directed produces at most $\sum_v|\req(v)|$ slices.
\end{enumerate}
\end{theorem}

The hardness proof encodes a CNF formula: one switch per variable chooses a branch that provides $t_i$ or $f_i$, the branches merge with \texttt{any}, and one gate per clause requires the facts that falsify all its literals and guarantees \p{bad}. The output requires \p{bad}, so a run misses it exactly when no clause is falsified, that is, when the formula is satisfiable~\cite{cook1971complexity}. In practice, slices are small and contain few choice points, which is why strategies with small slices scale (Section~\ref{sec:rq3}).

\subsection{Incremental Recertification}

Teams change: a prompt is rewritten, a model is swapped, a join policy is relaxed. Slices make re-verification local.

\begin{theorem}[Incremental recertification, T8]\label{thm:inc}
Let a change $\delta$ modify node $a$, and let $\Delta$ be the symmetric difference of $a$'s old and new guarantees. The dynamic findings $\Fd{\sigma}\setminus\Fd{\emptyset}$ of a slice $\sigma$ are unchanged unless $\sigma$ intersects $\mathit{Dep}(a,\delta)$, where
\begin{itemize}
\item $\mathit{Dep}=\{a\}$ for a change of oracle, kind, routing or join policy;
\item $\mathit{Dep}=\anc^*(a)$ for a change of $\req(a)$ or $\decl(a)$;
\item $\mathit{Dep}=\anc^*(Y)$ with $Y=\{a\}\cup\{y\in\desc(a):\req(y)\cap\Delta\neq\emptyset\}$ for a change of $\gua(a)$.
\end{itemize}
An edge change $(u,v)$ is treated as a change of $u$ and $v$ plus the consumers below $v$ of $u$'s face-value output, with ancestors taken in both the old and new graph; slices that lose convexity are re-evaluated. $\Fd{\emptyset}$ is recomputed in linear time.
\end{theorem}

\emph{Proof idea.} An outside node is taken at face value, so its oracle, kind, routing and policy are invisible to $H_\sigma$. A requirement only matters at its node, which affects $\sigma$'s findings only if the node lies in $\sigma$ or below a member, that is, if $\sigma$ meets $\anc^*(a)$. A guarantee change alters contents only in the bits of $\Delta$, and those bits matter only at nodes that require them (and at $\omega$, which requires the goals).

\section{Evaluation}\label{sec:eval}

\subsection{Implementation}

The library \texttt{slicing} (Python, about 2{,}200 lines) implements the team model with property sets as bit masks, the exact and hybrid semantics, slice enumeration and the strategies, derived and declared contracts, partition summaries (Theorem~\ref{thm:abs}d), the checkers and baselines, the diagnosis of classes, incremental recertification, the topology generator, and the injector. Teams are written in a small JSON specification language (Appendix~\ref{app:grammar}). Two independent oracles serve as ground truth for conformance testing. The \emph{model oracle} enumerates every contract-respecting model: all switch choices, all admissible contributor sets (not only minimal ones), all failure sets with $|F|\le f$ (not only maximal ones), and all evidence assignments between the realized minimum and that minimum plus every relevant property. The \emph{replay oracle} enumerates all runs of $H_\sigma$ and replays each with an evaluator that shares no code with the checker's enumerator. Proof obligations use Z3~\cite{demoura2008z3} version \resZThreeVersion{}.

\subsection{Experimental Setup}\label{sec:setup}

The experiment plan, with hypotheses, metrics, tests and decision rules, was written before any experiment ran and is part of the replication package; deviations are logged there and summarized in Section~\ref{sec:threats}.

\textbf{Benchmark.} The generator builds seven topologies: chain, tree, fork-join, layered DAG, series-parallel, random DAG, and \emph{mixed} (series-parallel with switches and \texttt{any}-joins). It assigns contracts in topological order, drawing each requirement from a sound lower bound on the node's content (a must-analysis in the style of monotone data-flow frameworks~\cite{kildall1973unified,kam1977monotone}), so generated teams are clean by construction; the exact semantics confirms this on every benchmark team. Default parameters: a quarter of the nodes are gates, agents draw from three oracles, each node has up to two requirements, two goals, and $f=1$. The injector then adds exactly one defect of a chosen class at a random place and records the ground truth: the class, the root-cause nodes, and the symptom keys the defect must produce (verified with the exact semantics). Goal-related defects are inserted as a release stage before the output; fact-related defects are inserted on a random edge, with a fresh consumer. The defect classes are A1--A4, S1, S2--S6b, plus \emph{clean} teams and four \emph{decoys}: structures that look suspicious but are safe (an \texttt{any}-join whose branches claim all goals; shared-oracle reviewers backed by a gate; a switch whose both branches provide the fact; a fallible provider backed by an independent gate). For each of the 7 topologies, 2 sizes, 10 seeds and 16 classes we build one team, in a \emph{small} benchmark (5 or 8 nodes before injection; \resBenchNodesSmallMin--\resBenchNodesSmallMax{} after) and a \emph{medium} one (20 or 30 nodes; \resBenchNodesMediumMin--\resBenchNodesMediumMax{} after): \resBenchSmall{} plus \resBenchMedium{} teams. On the small benchmark, exhaustive enumeration of all convex slices up to size~5 gives the true depth and the true minimal manifesting slices.

\textbf{Baselines.} B1 is agent-level analysis (singleton slices). B2 is the exact whole-team checker; it returns a verdict and one witness per key, and we localize to the hull of the witness's contributing lineage, which is the most a whole-team counterexample says about location. B3 draws random convex slices matched in number and size to SL. B4 is a structural lint: coverage by set difference over all claims, ignoring ancestry and paths, with a count of claimers for critical goals. B5, added after the plan was frozen, is a pattern-based smell detector that flags the shapes of S2--S6 (an \texttt{any} join or switch between claimer and consumer, a shared oracle among claimers, a gate depending on agent-only provisions) without semantics. It shows what a careful checklist achieves.

\textbf{Metrics.} A checker \emph{detects} a defect if it reports the defect's primary symptom key. \emph{Recall} is the detection rate over defective teams; \emph{precision} is the share of reported keys that are in $\Sym(T)$. A clean or decoy team with any reported key is a \emph{false alarm}. Localization uses the top-ranked slice of the primary key: it is \emph{exact} if it is one of the true minimal manifesting slices, \emph{precise} if it lies within the hull of the root cause, a \emph{hit} if it intersects the root cause; the \emph{size ratio} is its size over $|N|$. The \emph{hidden rate} is the share of defects with depth at least~2.

\textbf{Statistics.} Seeds are the unit of replication: per-seed rates are paired across checkers. We use one-sided Wilcoxon signed-rank tests~\cite{wilcoxon1945individual} with Holm correction~\cite{holm1979simple}, Vargha--Delaney $\hat A_{12}$ effect sizes~\cite{vargha2000critique}, exact McNemar tests~\cite{mcnemar1947note} on paired team-level outcomes, and 95\% percentile bootstrap confidence intervals~\cite{efron1993introduction}, following Arcuri and Briand~\cite{arcuri2011practical}.

\textbf{Environment.} All experiments run on one machine (20 CPU cores, Linux, Python 3.12, NumPy, SciPy, Z3), with seeds fixed in the scripts. Each result file records the commit, library versions and wall time. One command regenerates all results, tables, figures and the numbers in this paper.

\subsection{RQ1: Formal Foundation and Expressiveness}\label{sec:rq1}

\textbf{Method.} We validate the theory in three ways. (i) The per-node steps of the proofs are SMT obligations over arrays from an uninterpreted sort of properties to Booleans, so each holds for every property universe and every contract; an obligation is valid if its negation is unsatisfiable. Six \emph{proof mutants} each change one definition (for example, letting declared evidence flow on); each must break the obligation that depends on it, which shows that the obligations are not vacuous. (ii) Conformance: on \resWildTeams{} random ``wild'' teams with arbitrary contracts, policies, switches and faults (3--7 inner nodes) and on \resBenchTeams{} small benchmark teams, we compare the implementation with the two oracles and check each theorem's statement directly. (iii) We check the hardness reduction on \resReductionFormulas{} random 3-CNF formulas and the fooling sets of Theorem~\ref{thm:sep}b.

What is mechanized and what is not: the SMT obligations cover the per-node steps (transfer monotonicity, face-value domination, join and halt steps, locality of declared evidence, the must-analysis, and the countermodels). The inductions over topological order that lift these steps to whole teams, the separation families, and the complexity results are proved on paper (Appendix~\ref{app:proofs}) and tested exhaustively on bounded instances, but not mechanized in a proof assistant.

\answer{RQ1}{Yes. A slice is a convex set of agents with a hybrid semantics and a derived contract. Slice abstraction is exact over partitions with an acyclic quotient (T2), the singleton slicing is exactly agent-level analysis (T1), and slice-level analysis recovers every agent-level finding (T4c) while revealing defect families that no analysis of singleton views can find without false alarms (T4a,b). Per-node proof steps are SMT-checked, and \resConformanceComparisons{} oracle comparisons show zero mismatches. Exact contracts are relations, not single assumption-guarantee pairs (T2c), and a finding of a strict sub-slice can be a false alarm (T3c, T5e).}

\begin{itemize}

\subsection{RQ3: Cost, Slicing Strategy, and Evolution}\label{sec:rq3}

\textbf{Slice size (E4).} On the small benchmark we run exhaustive-$k$ for $k=1,\ldots,5$. Fig.~\ref{fig:ksweep} shows recall of the injected symptom by $k$ and class, with 95\% bootstrap bands over seeds. Recall over all classes rises from \resRecallKOne{} at $k=1$ (agent level) to \resRecallKTwo{} at $k=2$, \resRecallKThree{} at $k=3$, and \resRecallKFour{} at $k=4$, and stays there; the gain from $k$ to $k+1$ first drops below one percentage point at $k=\resSaturationK$ (H3.2 supported). S2 and S3 need $k=2$; S4, S6a and S6b need $k=\ell+2$ for $\ell$ intermediate hand-offs. The number of slices grows from \resSlicesKOne{} at $k=1$ to \resSlicesKFive{} at $k=5$ per team on average; the false-alarm rate on clean and decoy teams stays at \resAlarmKFive{} for every $k$. Larger slices stop paying off once they contain the interacting components: after that they only add members whose behavior is irrelevant to the defect, and they make the explanation larger.

\textbf{Scalability (E5).} We generate teams of 10 to 5{,}000 nodes in four topologies, inject one hidden defect, and run each strategy with a budget of \resScaleBudget{}~s per team (\resScaleTeams{} teams). Fig.~\ref{fig:scale} and Table~\ref{tab:scale} report wall time. But on these teams the exact whole-team checker is the cheapest method of all (slope \resSlopewholefree; \resTimeBigwholefree~s at 5{,}000 nodes): without switches and with \textsf{all}-joins a team has a single fault-free run plus one run per failure set, and checking it is a linear pass. Singleton and window-2 slices never time out. SL, however, also times out on \resTimeoutsSLmixed{} of 90 mixed teams: its goal-directed and region slices are hulls that grow with the team and contain many choice points, and slices that exceed the per-slice run budget are skipped. As a result SL's detection drops to \resDetectSLmixed{} on mixed teams (\resDetectSLfree{} on switch-free teams), while the whole-team checker detects every defect on the teams it finishes. Exhaustive enumeration of convex slices up to size~3 was attempted on \resExhRun{} teams and skipped on \resExhSkipped{} larger ones (more than three million candidate subsets); Table~\ref{tab:convex} shows how the number of convex slices grows quadratically on chains and much faster on layered teams. H3.1 is therefore only partly supported: slicing is polynomial when slices have few choice points, and its cost advantage over exact whole-team checking appears only on choice-rich teams, where it is also limited by the same choice points inside large slices.

\textbf{Sensitivity, ablation and false alarms (E7).} \emph{Sensitivity.} Varying the share of gates (0, 0.25, 0.5), the number of distinct oracles (1, 3, 6) and the maximum number of requirements per node (1, 2, 3) on \resSensTeams{} teams of 15 nodes does not change the outcome: SL finds every hidden defect in every configuration (minimum recall \resSensMinRecall), B1 finds none, and SL reports \resSensFalseKeys{} false keys (Table~\ref{tab:sens}). \emph{Ablation} (Table~\ref{tab:ablation}, \resAblTeams{} teams). If the analysis treats every join as \textsf{all}, S2 and S3 are no longer detected (\resAbljoinsasallSTwo{} and \resAbljoinsasallSThree); without fault reasoning, S4 and S6a are lost (\resAblnofaultsSFour{} and \resAblnofaultsSSixa). Each part of the semantics is thus responsible for specific classes; S6b depends on neither. Dropping one interior node from \resAblNonconvexTried{} slices to make them non-convex produced \resAblNonconvexFalse{} false keys on these teams. So in our benchmark convexity is not needed to avoid false alarms; we keep it because it makes the entry environment well defined (Lemma~\ref{lem:convex}) and the abstraction theorem hold. \emph{False alarms on unstructured teams.} The benchmark teams are built from clean teams, which may flatter precision. On \resWildFATeams{} random wild teams with arbitrary contracts, policies and switches, we ran every convex slice of size at most~3: \resWildFAFalse{} of \resWildFAFindings{} findings (\resWildFARate) are not symptoms of the team, and \resWildFASliceRate{} of the \resWildFASlices{} slices report at least one false key. These are the false alarms of Theorem~\ref{thm:sound}c: a switch or an \textsf{all}-join outside the slice is taken at face value. \subsection{Discussion}\label{sec:discussion}

\textbf{Which defects hide?} Every defect whose mechanism is a join policy, a shared model, or a conditional guarantee is hidden at agent level. The reason is structural (Proposition~\ref{prop:al}): a singleton slice sees the union of its inputs, never the choice a join makes; it sees one agent fail, never two agents fail together; and it sees a gate's inputs, never where they came from. Defects whose mechanism is a missing claim are visible at agent level. Bypasses (S5) are visible at the switch but are better explained by the slice that contains the merge.

\textbf{Depth is small but not one.} Most hidden defects in our benchmark have depth two to four, and every one is found by slices of at most four nodes. This matches the intuition that a blind spot is a relationship between a few components. Depth grows with the number of hand-offs between the interacting components (S4, S6), not with the size of the team.

\textbf{Which join policies are dangerous?} An \texttt{any} or quorum join is not dangerous by itself: the decoy in which every branch claims every goal is safe, and B5's alarms on those decoys show that the shape is not the problem. The danger is a join whose branches carry \emph{different} guarantees. Slice-level analysis separates the two cases because it computes what each branch establishes.

\textbf{Choosing a strategy.} For certification, the whole team is the right tool when the team has few switches and quorum joins: it is exact and, as E5 shows, very cheap. For choice-rich teams, a partition with an acyclic quotient (Theorem~\ref{thm:abs}d) keeps each part's choices local. For diagnosis, the combined strategy (singleton, window-2, region, goal-directed) found every injected defect with small explanations on teams up to a few hundred nodes. Goal-directed slices are the best single strategy for detection; window-2 gives the smallest explanations and never timed out; region slices give the most readable ones (a whole fork-join region). On large choice-rich teams, slices should be capped by their number of choice points rather than by their number of members, since choice points, not members, drive the cost (Theorem~\ref{thm:cx}b). When a team has few choice points, exhaustive slices up to size four are affordable and give exact localization. Findings of strict sub-slices should be confirmed by replaying their witness on the whole team before they are reported to an engineer.

\textbf{Slices versus failure attribution.} Automated failure attribution names the agent and step responsible for a failed run~\cite{zhang2025which}. Slices answer a different question before any run: which group of agents, under which obligation, makes a failure possible. The two are complementary: a minimal manifesting slice is a hypothesis for where attribution should look.

\subsection{Threats to Validity}\label{sec:threats}

\textbf{Construct validity.} Contracts are declared, not measured. Whether an LLM agent establishes \p{design} or a gate's tests are meaningful is outside the model. Our findings are relative to the declared contracts: a team we call safe may fail if a contract is wrong, and a team we call unsafe may be fine if a contract is too weak. Injected defects are small gadgets; real defects may be larger or interleaved. Properties are atomic facts; real artifacts have quality on a scale. The robust semantics treats a failure as ``provides nothing''; a model that provides wrong content while claiming success is covered only insofar as downstream gates check it.

\textbf{Internal validity.} The generator, injector and checkers come from the same authors and share the data model. We mitigated this with an independent model oracle and replay oracle, a fresh exact verification of every ground-truth key, proof mutants, decoys, and ablations. One shared misreading was found this way (Section~\ref{sec:rq1}); others may remain. The hidden-class results are close to guaranteed by Theorem~\ref{thm:sep}; the experiment's value lies in confirming that the theory and the implementation agree across topologies and in measuring localization and cost. Baseline B5 was added after the plan was frozen. The deviation is logged.

\textbf{External validity.} Teams are acyclic; loops are unrolled once, and shared mutable state is not modeled. The nine encoded designs are a sample from published papers, encoded by us with a written protocol; other encoders might choose other contracts, which is why we report a sensitivity analysis. Benchmark sizes are small for exhaustive ground truth and medium otherwise; scalability is measured on larger generated teams without ground-truth depth.

\textbf{Conclusion validity.} With ten seeds per configuration, Wilcoxon tests have a floor on attainable $p$-values; we report effect sizes, exact counts and McNemar tests on teams as well. Many outcomes are at 0\% or 100\%, so confidence intervals are degenerate; we report them anyway. Multiple comparisons are Holm-corrected within each hypothesis.

\section{Related Work}\label{sec:related}

\textbf{LLM multi-agent systems for software engineering.} Role-based teams (MetaGPT~\cite{hong2024metagpt}, ChatDev~\cite{qian2024chatdev}, self-collaboration~\cite{dong2024selfcollab}), code-generation pipelines (AgentCoder~\cite{huang2023agentcoder}, MapCoder~\cite{islam2024mapcoder}), issue-resolution pipelines (Agentless~\cite{xia2025agentless}, MAGIS~\cite{tao2024magis}), and general frameworks (AutoGen~\cite{wu2024autogen}, CAMEL~\cite{li2023camel}, multi-agent debate~\cite{du2024debate}, mixture-of-agents~\cite{wang2024moa}) define the topologies we encode. He et al.\ survey LLM-based multi-agent systems in software engineering and call for principled ways to engineer them~\cite{he2025llmmas}; the broader surveys of LLMs for software engineering make the same point~\cite{hou2024llm4se,fan2023llmse}. None of these works reason about sub-teams as contracts before execution.

\textbf{Evaluating and testing agents.} Benchmarks evaluate the output of a run~\cite{jimenez2024swebench,liu2024agentbench,yehudai2025survey}. ToolEmu emulates tools to expose risky agent actions~\cite{ruan2024toolemu}; AgentDojo and indirect prompt injection studies attack single agents through their inputs~\cite{debenedetti2024agentdojo,greshake2023not}. Failure taxonomies and attribution~\cite{cemri2025why,zhang2025which} analyze executions after the fact. Our analysis is static and compositional and needs no run.

\textbf{Guardrails and runtime enforcement.} Llama Guard and NeMo Guardrails filter one model's inputs and outputs~\cite{inan2023llamaguard,rebedea2023nemo}; AgentSpec enforces rules on one agent's actions at run time~\cite{wang2026agentspec}. These are components in our model: a guardrail is a gate or an agent with a contract. Slicing asks whether the guardrails, placed where they are, justify the team's goals.

\textbf{Contracts and assume-guarantee reasoning.} Design by contract~\cite{meyer1992applying}, assume-guarantee reasoning for networks of processes~\cite{misra1981proofs}, rely-guarantee for interference~\cite{jones1983tentative}, composition of specifications~\cite{abadi1993composing}, interface automata~\cite{dealfaro2001interface}, and contract theories for system design~\cite{benveniste2018contracts} provide the foundation. Circular assume-guarantee rules are sound only under side conditions; our acyclic-quotient condition is the graph form of such a side condition. Learning assumptions for compositional verification~\cite{cobleigh2003learning} computes the weakest assumption of a component; our derived entry assumptions are the analogue for a slice, and our result that exact slice contracts are relations rather than pairs echoes the observation that interfaces need input-dependent guarantees. What is new is the choice of \emph{which} sub-structures to treat as components, the hybrid semantics that makes any convex sub-structure analyzable, and the use of slice size as a measure of how hidden a defect is.

\textbf{Program slicing and fault localization.} Weiser's slices~\cite{weiser1984program} and dependence-graph slicing~\cite{horwitz1990interprocedural,ferrante1987program} select the statements relevant to a criterion; our goal-directed strategy is a backward slice over the team graph. Fault localization ranks program elements by suspiciousness~\cite{wong2016survey,jones2005empirical}, and delta debugging isolates failure-inducing changes~\cite{zeller2002simplifying}. Minimal manifesting slices are a localization by construction: a smallest component set whose contract-level analysis already exhibits the defect. Single-entry single-exit regions and dominators~\cite{johnson1994program,lengauer1979fast} define our region strategy, and workflow nets~\cite{vanderaalst1998application} are a related formalism for process topologies with fork and join.

\textbf{Redundancy, independence and system safety.} N-version programming relies on independent versions~\cite{avizienis1985nversion}; Knight and Leveson showed that independently developed versions fail together more often than independence predicts~\cite{knight1986experimental}, and Littlewood and Miller modeled such coincident failures~\cite{littlewood1989conceptual}. Our class S4 is the contract-level form of this problem for agents that share a model. Feature interactions in telecommunications~\cite{calder2003feature} are an earlier case of defects that arise only when components are combined. Systems-theoretic safety analysis treats safety as a property of interactions rather than components~\cite{leveson2011engineering}, the stance that slicing makes operational. Model checkers for multi-agent systems verify epistemic and temporal properties of agent models~\cite{lomuscio2017mcmas}; we target a simpler, contract-level question that scales to thousands of agents with polynomial strategies.

% =====================================================================
\section{Conclusion and Future Work}\label{sec:conclusion}

A team of AI agents can fail even when every agent keeps its contract, and the failure lives in a relationship among a few agents. Agent slicing makes such relationships first-class: a slice is a convex set of agents with its own contract, analyzed with the rest of the team at face value. The theory recovers agent-level analysis exactly, is strictly more expressive, composes over partitions with an acyclic quotient, and supports local recertification. The experiments show that a large share of injected defects are invisible at agent level, that small slices find all of them, and that their main value over whole-team checking is a precise explanation of where the defect lives.

Future work includes cycles and retries beyond bounded unrolling, shared mutable state, probabilistic and statistical contracts (an agent that establishes a property with some probability), discovering contracts from documentation and traces, and validating slice findings against executions of real agent teams.

\section{Proofs}\label{app:proofs}

Throughout, content, outputs and keys refer to Definitions~\ref{def:run}--\ref{def:hybrid}. We write $o_\rho$, $c_\rho$ for a run's outputs and contents and ``$v$ reached in $\rho$'' for reachability. Inductions run over a fixed topological order.

\textbf{Per-node facts.} The following hold for a single node and are the SMT obligations of Table~\ref{tab:proofs}. (L1) If $c\subseteq c'$ and ``$v$'s oracle sound'' implies ``sound'' in the second setting, then $o\subseteq o'$. (L2) The exact output is below the face-value output $c'\cup\gua(v)$ whenever $c\subseteq c'$. (L3) The union of outputs of a contributor subset is below the union of all delivered outputs when each is pointwise smaller. (L4) Missing requirements $\req\setminus(c\cup\decl)$ are antitone in $c$. (L5) The output is monotone in the evidence. (L6) A halted contributor contributes what an excluded contributor contributes. (L7) Any nonempty selection of entries that all carry $\env$ yields $\env$. (L10, L11) A failed oracle yields $o=c$, below the fault-free output. (L12, L13) Declared evidence enables application but never reaches the output.

\textbf{Lemma~\ref{lem:w} (worst case).} ($\Leftarrow$) A run is the model with $E(v)=c(v)\cup\decl(v)$. ($\Rightarrow$) Given a model with evidence $E$, consider the run with the same choices and failures. By induction, the run's content at each node is a subset of the model's content (L5 and L3), so the run's missing requirements and goals are supersets of the model's (L4). A model may reach a node the run also reaches, since reachability depends only on choices. Robust keys: the goal-key condition is the same in both. \qed

\textbf{Lemma~\ref{lem:m} (minimal choices).} Shrinking a contributor set shrinks content at that node (L3) and, by induction with L1, everywhere below; adding failures shrinks outputs (L10). Reachability does not depend on contributor sets or failures. So every key of a run is a key of the run with minimal contributor sets and maximal failure sets that agrees on switches. Among sets of size exactly $q$, only inclusion-minimal content values need to be kept, which the implementation does. \qed

\textbf{Lemma~\ref{lem:h} (halting).} A halted delivery makes some successors receive fewer deliveries. If a successor is still reached, its content is that of a run that excludes the halted contributor (L6), which is a legal contributor choice when the remaining deliveries meet the policy; if it is not reached, every key in its sub-graph is a key of some run reaching it with fewer contributors, or does not occur. \qed

\textbf{Lemma~\ref{lem:convex} (convexity).} If $x\notin\sigma$ were a descendant of $u\in\sigma$ and an ancestor of $w\in\sigma$, the path $u\leadsto x\leadsto w$ would leave $\sigma$. An outside predecessor $x$ of a member $w$ is an ancestor of $w$, so it is not a descendant of any member. Contracting $\sigma$: a cycle in the contracted graph must pass through the contracted node and leave and re-enter it, which gives a path from a member through an outside node to a member. Conversely, such a path yields a cycle. \qed

\textbf{Lemma~\ref{lem:face} (face value dominates).} By induction over the topological order, we show for every node $v$: reached in $\rho'$ implies reached in $\rho$, and $c_{\rho'}(v)\subseteq c_\rho(v)$, $o_{\rho'}(v)\subseteq o_\rho(v)$. \emph{Delivery:} if $(u,v)$ is delivered in $\rho'$, then $u$ is reached in $\rho$ by induction; if $u\in\sigma$ the switch choice is the same; if $u\notin\sigma$, $u$ delivers to all successors in $\rho$. \emph{Reachability:} for $v\in\sigma$, every in-edge from outside $\sigma$ is delivered in $H_\sigma$, and member in-edges are delivered in $\rho$ whenever they are in $\rho'$, so the policy is met in $\rho$; for $v\notin\sigma$, reachability in $H_\sigma$ needs only one delivered in-edge. \emph{Content:} for $v\in\sigma$ with contributor set $C$ in $\rho'$, the same $C$ is admissible in $\rho$; members of $C$ contribute outputs that are larger in $\rho$ by induction, and outside members contribute their face-value output, which by induction (applied to $\sigma=\emptyset$, i.e.\ the cone) dominates their output in $\rho'$; L3 gives the claim. For $v\notin\sigma$, all delivered in-edges contribute in $\rho$, a superset of $\rho'$'s contributors. \emph{Output:} if $v\in\sigma$, its oracle is in $F'$ if and only if it is in $F'\cap\orc(\sigma)$, so L1 applies; if $v\notin\sigma$, L2 applies. \qed

\textbf{Proposition~\ref{prop:al}.} In $H_{\{v\}}$ every node is reached in some run: $v$ is always reached (all its in-edges are entries), and every other node is reached when $v$'s switch, if any, picks a successor on a path to it. By Lemma~\ref{lem:face} with $\emptyset\subseteq\{v\}$, contents in $H_{\{v\}}$ are below face-value contents, so every static key persists (L4): $\Fd{\emptyset}\subseteq\Fd{\{v\}}$. If $v$ applies and is not a switch, its content is $\env_{\{v\}}(v)=\cone(v)$ for every contributor choice (all contributors are entries; L7), its output is the face-value output, and the run equals the face-value run, which has only static keys. \qed

\textbf{Theorem~\ref{thm:conserv}.} Immediate from Definition~\ref{def:al} and Proposition~\ref{prop:al}. \qed

\textbf{Theorem~\ref{thm:abs}.} (a) Let $T'$ be $T$ with $\sigma$ replaced by a macro node $M$ with the same entry and exit edges. By Lemma~\ref{lem:convex} the contracted graph is acyclic, so runs of $T'$ can be evaluated in topological order. A run of $T$ restricts to an entry pattern of $\sigma$ (which entry edges are delivered and with which content) and an internal run; by definition of $\Beh_\sigma$, the exit outcome and the member keys are in $\Beh_\sigma$ for that pattern. Conversely, an outcome in $\Beh_\sigma$ for the entry pattern produced by a run of $T'$ comes from an internal run of $\sigma$ that, combined with the outside choices, is a run of $T$ with the same outside contents. Since keys outside $\sigma$ depend only on outside contents and reachability, and member keys are carried by the macro, $\Sym(T)=\Sym(T')$. Contents are tracked symbolically: each member's content is $\bigcup_{e\in \mathit{flow}}\mathit{content}(e)\cup\mathit{added}$, where $\mathit{flow}$ is the set of entry edges whose content reaches it; this makes the summary independent of the concrete entry contents, and the implementation keys the cache on the bits members require.
(b) The replacement component's behavior contains $\Beh_\sigma$ whenever the entries carry at least $A^d$, by validity, and is arbitrary otherwise; so every run of $T$ maps to a behavior of the abstracted team with the same outside contents or smaller ones (L1, L4). A goal key of $T$ is then a goal key of the abstracted team.
(c) The obligation C2 of Table~\ref{tab:proofs} states, over 4-bit vectors, that for every pair $(A,G)$ there is an environment on which ``if $A$ then $G$'' differs from the derived guarantee $g_1[r_1]\cup g_2[r_2]$; Z3 proves it.
(d) Induction over the quotient's topological order, applying (a) to each part in turn; at each step the part's entries come from parts already evaluated. The cyclic example is in the text: each flat contract is valid in isolation when its entries are assumed to carry the assumption, and the two discharge each other, but in $T$ neither $a$ nor $c$ ever receives what it requires. \qed

\textbf{Theorem~\ref{thm:sound}.} (a) $\Fd{N}=\Sym(T)$ because $H_N$ has no outside node; a reported witness of $H_N$ is a run of $T$. The partition certification computes $\Sym(T)$ by Theorem~\ref{thm:abs}d. (b) A lifted witness gives a run of $T$ that agrees inside $\sigma$ and reaches the symptom node; outside nodes in $T$ have content at most their face-value content (Lemma~\ref{lem:face}), so the missing property is still missing (L4). (c) By the example in the text, verified by the implementation. \qed

\textbf{Theorem~\ref{thm:sep}.} (a) We give the families; each is checked for small parameters by the test suite and the conformance experiment. \emph{S2}: a fork into $m\ge 2$ branches, branch $i$ a chain of $\ell_i$ agents whose first agent claims goal $g_i$, all joined by a quorum $q<m$. Every goal is claimed by an ancestor of $\omega$ and no node has a requirement, so $\Fd{\emptyset}=\emptyset$; the join's singleton sees the union of its inputs, and no other singleton is a switch or fails a requirement, so by Proposition~\ref{prop:al} $\AL=\emptyset$ (with $f=0$). A run in which the join uses $q$ branches other than $i$ misses $g_i$. The slice $\{b_i,J\}$ of the last agent of branch $i$ and the join manifests it: $b_i$'s entry carries $g_i$ at face value, and the join can choose another contributor. \emph{S3}: as S2 with a fact instead of a goal and a consumer after the join. \emph{S4}: two agents on one oracle, both claiming a critical goal, separated by $\ell$ hand-offs, with $f=1$. A singleton containing one claimer can fail only that claimer, and the other claimer outside applies at face value; so $\AL=\emptyset$. Failing the shared oracle removes both claims. $\hull\{r_1,r_2\}$ has $\ell+2$ nodes and manifests the robust key. \emph{S6a}: an agent providing $x$, $\ell$ hand-offs, a gate requiring $x$ and guaranteeing a critical goal. The singleton of the agent fails it but the gate outside applies at face value; the singleton of the gate sees $x$ at face value. The hull of agent and gate manifests the key. \emph{S6b}: a gate that does not provide $y$, an agent requiring $y$ and guaranteeing $z$, $\ell$ hand-offs, a gate requiring $z$ and guaranteeing a goal. $\AL$ contains $\key{assume}{a}{y}$, but in every singleton the goal gate applies at face value, so the goal key is in the hull of agent and gate only.
(b) For a predicate on singleton views that is sound, the unsafe team must be flagged through some view; that view occurs in a safe team, which is then flagged too. The three constructions are in the text and in the replication package, and the conformance experiment checks that the safe teams are safe, the unsafe team is unsafe, and the views are covered.
(c) A key located at $v$ in $\Fd{\{v\}}$ concerns $v$'s own requirements, which are unmet at face value; in $H_\sigma$ with $v\in\sigma$, $v$ is reached in some run (liveness and Lemma~\ref{lem:face} applied to $\sigma\subseteq N$) and its content is below face value (Lemma~\ref{lem:face} with $\emptyset\subseteq\sigma$), so the requirement is still unmet (L4). \qed

\textbf{Theorem~\ref{thm:loc}.} (a) $N$ manifests every symptom (Theorem~\ref{thm:sound}a); manifesting slices form a finite nonempty family, which has inclusion-minimal elements. (b) The fork-join example has two minimal slices. If $\MMS(\kappa)=\{\sigma\}$, the intersection is $\sigma$, which manifests. Conversely, the intersection of convex sets is convex; if it manifests $\kappa$ it is a manifesting subset of each minimal slice, so all minimal slices equal it. (c) Let $L$ be the contributing lineage of the symptom node $x$ in a witness run $\rho$ of $T$ and $h=\hull(L)$. Run $H_h$ with $\rho$'s choices on $h$ and failures $F\cap\orc(h)$. By induction over $L$ in topological order, every node of $L$ is reached and has the same content as in $\rho$: its contributors in $\rho$ are in $L\subseteq h$, they are reached with the same outputs, the switch choices are the same, extra entry deliveries can only help a quorum be met, and a node of $L$ whose oracle failed in $\rho$ has that oracle in $\orc(h)$. So $x$ misses the same property. For an \texttt{assume} or \texttt{goal} key this is $\kappa$; for a robust key, either $\kappa\in\Fd{h}$ or the stronger goal key for the same property is. (In \resWildTeams{} wild teams the stronger alternative never occurred.) (d) A lifted witness of $H_{\sigma'}$ exhibits the key by definition. If $\sigma'\setminus\sigma$ has no switch and no \textsf{all} or quorum join, then adding these nodes as members changes no delivery (they deliver everywhere and are reached on any input, as at face value) and, with the same contributor sets, contents can only shrink (Lemma~\ref{lem:face}), so the key persists (L4). (e) The five-node team of Section~\ref{sec:approach}: with $\sigma=\{s,x,y\}$ the output is outside and reached on one input, giving a goal key; with $\sigma'=\sigma\cup\{\omega\}$ the output requires both inputs and the key disappears. \qed

\textbf{Theorem~\ref{thm:overlap}.} Keys are triples of kind, node and property, defined independently of $\sigma$. Merging is set union, and the localization keeps, per key, the list of manifesting slices, from which the inclusion-minimal ones are selected. The last claim is Definition~\ref{def:depth}. \qed

\textbf{Theorem~\ref{thm:cx}.} (a) Membership: a run is a polynomial certificate, evaluated in linear time (Definition~\ref{def:run}); by Lemma~\ref{lem:w} runs suffice. Hardness: the reduction in the text is polynomial; for each assignment there is exactly one run (the switches), in which variable $i$ contributes exactly one of $t_i,f_i$; clause gate $j$ applies iff all its literals are false; so $\omega$ misses \p{bad} iff no clause is false, i.e.\ iff the assignment satisfies the formula. Safety is the complement. (b) Each internal run evaluates members once and propagates to outside descendants once, each in $O(|N|+|E|)$ word operations on property bit sets. (c) An antichain of $w$ nodes has $2^w$ convex subsets; for $k$ fixed, enumerating subsets of size $\le k$ and testing $\hull(S)=S$ with bit sets gives $O(|N|^k)$ tests. (d) Each strategy emits at most a constant number of slices per node (window, band, region) or per requirement (goal-directed), each a hull computed in $O(|N|+|E|)$. \qed

\textbf{Theorem~\ref{thm:inc}.} Write $\delta$ for the change. (i) Oracle, kind, routing and policy of $a$ enter $H_\sigma$ only if $a\in\sigma$, since outside nodes are at face value. (ii) $\req(a)$ and $\decl(a)$ enter the applicability of $a$ (only if $a\in\sigma$) and the keys at $a$, which are dynamic findings only if $a$ is reached by an internal run's propagation, i.e.\ if $a\in\sigma\cup\desc(\sigma)$, i.e.\ if $\sigma\cap\anc^*(a)\neq\emptyset$. (iii) A change of $\gua(a)$ changes face-value outputs and run contents only in the bits $\Delta$. Bits of $\Delta$ affect applicability and keys only at nodes $y$ with $\req(y)\cap\Delta\neq\emptyset$ (for $\omega$: goals), all in $\desc(a)$, and at $a$ itself through its output. If $\sigma$ contains no ancestor-or-self of a node of $Y$, then no member applies differently, no key at a node of $Y$ can be a dynamic finding of $\sigma$ (it would be a descendant of a member), and the remaining contents differ only in irrelevant bits. Edge changes combine (i)--(iii) for both endpoints, with the face-value output of $u$ as $\Delta$ and ancestors in both graphs. The conformance experiment compares incremental and full re-verification after random changes on every wild and benchmark team. \qed

\section{Team Specification Language}\label{app:grammar}

Teams are JSON documents. Unlisted fields take the defaults shown.

{\scriptsize
\begin{verbatim}
team   ::= { "name": str, "goals": [prop],
             "critical": [prop], "fault_budget": int,
             "nodes": [node], "edges": [[id, id]] }
node   ::= { "id": id, "kind": "agent" | "gate",
             "req": [prop], "gua": [prop],
             "decl": [prop]        (default [])
             "oracle": str         (agents only)
             "route": "fork" | "switch" (default fork)
             "join": "all" | "any" | "quorum:q" }
prop   ::= name | name "@" view
\end{verbatim}
}

\texttt{IN} and \texttt{OUT} are added if missing; \texttt{IN} guarantees the input facts, and \texttt{OUT} requires the goals. A property with a view suffix (\p{spec@summary}) is a different property from \p{spec@raw}; this is how interface gaps (S1) are expressed.
